# 咩咩润色工具 —— SillyTavern 扩展

## 这是什么

一个本地 SillyTavern 扩展，做两件事：**正文翻译** 和 **正文润色**。

它由酒馆助手脚本「咩咩工具箱 1.0.1」拆分而来，**只保留工具箱里的正文翻译 / 润色模块**，工具箱中的其余模块（含时间线相关部分）已全部移除。

- 来源：`咩咩工具箱-1.0.1.json`（酒馆助手脚本导出，只读，未改动）
- 模块版本：正文翻译 / 润色 `0.2.19`（原始代码里的版本号）
- 本扩展版本：`1.0.0`

## 它有什么功能（沿用原模块，未新增）

面板是右下角一个「🐑 正文翻译」按钮，点开是「咩咩润色工具」面板。

- 两种模式：**翻译**（translate）/ **润色**（polish），可切换。
- 提示词库：内置「翻译」「润色」两个默认模板（只读，可复制），支持新建、编辑、导入、导出自己的提示词模板。模板按模式分别保存与选用。
- 设置按角色卡保存：目标语言、要求、术语表、前置 / 后置提示词、思考模式、保护标签。
- 接口设置：API 地址、模型名、最大 token、等待上限、连接测试、获取模型列表。密钥可选记在浏览器本地，或只保留在当前页面。
- 手动处理 / 自动处理：手动点「处理」按钮，或打开自动处理后从下一条完整 AI 回复开始自动处理。
- 可恢复：处理前会备份原文，随时可「恢复原始正文」。
- 「发送时使用原文」：把翻译 / 润色后的正文显示给你看，但发给 AI 时换回对应原文。
- 保护标签：指定标签内部的文字不送去翻译（`<story_scene>` 之类的外层标签始终保护）。
- 调试视图：可以看到最近一次处理请求和主请求的实际内容（密钥自动打码）。

## 怎么装

1. 把 `咩咩润色插件` 整个文件夹复制到酒馆的扩展目录：
   - 只给当前用户用：`SillyTavern/data/<你的用户名>/extensions/咩咩润色插件/`
   - 给所有用户用：`SillyTavern/public/scripts/extensions/third-party/咩咩润色插件/`
2. 刷新酒馆页面（F5）。
3. 打开「扩展」菜单，确认「咩咩润色工具」已出现在列表里且是启用状态。
4. 右下角应该出现「🐑 正文翻译」按钮，点它打开面板。

目录里必须有 `manifest.json` 和 `index.js` 两个文件，`manifest.json` 的 `js` 字段指向的就是入口文件 `index.js`。

### 装之前请注意

- 如果原本装了独立的「正文翻译」酒馆助手脚本，请先停用它，否则两边会各自建一套面板。
- 本扩展的配置存在酒馆的扩展设置里（`extensionSettings['meeme_translation_v1']`，就是原脚本用的那个扩展 ID）。API 密钥存在浏览器 `localStorage`（键名 `meeme_translation_key_v1`），不写进扩展设置。

## 做了什么（拆分与迁移记录）

源文件 `content` 是一段 2,334,152 字符、1235 行的 JS，结构是「外层包装 + 三个独立 IIFE」：

| 段 | 行号 | 内容 | 处理 |
| --- | --- | --- | --- |
| A 外层包装 | L2–L1235 | `const h=window.parent`、两条守卫（已装过就打开 / 与独立脚本冲突就 alert）、注释头 | 删除。守卫只服务于合并版，拆开后无对象；`h` 也随之无人使用 |
| B 时间线模块 | L8–L495 | 时间线业务 + 自带悬浮球 `.ts-orb` + 面板 `#meeme-ts-panel` + CSS + 事件绑定 | **整段删除**（2,057,123 字符） |
| C 正文翻译 / 润色 | L498–L1148 | 翻译 / 润色全部业务逻辑，自带面板 `#meeme-translation` 和入口按钮 | **保留**，只改宿主接口 |
| D 合并版菜单 | L1151–L1233 | 借用 B 的悬浮球做统一菜单，把两个面板收进一个球 | **整段删除**（208,801 字符）。它完全建立在 B 的悬浮球上（`timeline.root.querySelector('[data-open]')`、`.ts-panel`、`iconImage.src`），删掉 B 后无法成立 |

删掉 D 之后，C 自带的入口按钮恢复可见（D 原本会把它 `hidden=true` 藏起来）。这一点是刻意保留的：**入口仍然是原来那个**，没有新增任何界面元素。

### 宿主接口迁移（酒馆助手脚本 → ST 扩展）

C 段原来用到 5 个酒馆助手专属全局，逐个核对结果：

| 原用到的全局 | 扩展里怎么处理 |
| --- | --- |
| `getVariables({type:'extension',extension_id})` | 换成 `SillyTavern.getContext().extensionSettings['meeme_translation_v1']`。酒馆助手的「扩展变量」本来就存放在该扩展 ID 下的用户存档里，所以这是同一个存储位置，不是替代品 |
| `replaceVariables(..., {type:'extension'})` | 换成写 `extensionSettings` + `saveSettingsDebounced()`，同上 |
| `eventOn(event, fn)` | 换成 `eventSource.on(event, fn)`；原来靠 `handle.stop()` 退订，现在存 `{stop:()=>eventSource.removeListener(event,fn)}`，`cleanup()` 里的 `subs.forEach(s=>s.stop())` 不用改 |
| `setChatMessages([{message_id,message}], {refresh:'affected'})` | 换成直接写 `chat[id].mes`（连当前 swipe 一起写），再用 `getContext().updateMessageBlock(id, message, {rerenderMessage:true})` 重绘该楼层 |
| `formatAsTavernRegexedString(text,'ai_output','prompt',{depth})` | **换不了**。`SillyTavern.getContext()` 没有暴露酒馆正则的执行入口。已保留原来的 `typeof` 探测：拿不到就按原文处理，并在调试视图里标记 `promptRegexApplied:false`。详见「已知限制」 |

另外 `window.parent` 这套写法**保留未改**：扩展直接跑在页面里，`window.parent === window`，所以 `const host=window.parent` 依然成立，少改一处就少一处出错的地方。其余 `host.xxx` 用的都是标准浏览器接口（`document` / `fetch` / `localStorage` / `AddEventListener` / `AbortController` / `visualViewport` 等）。

## 已知限制

1. **酒馆正则可能不生效**：只有「发送时使用原文」这条路径会用到 `formatAsTavernRegexedString`。如果酒馆里装了正则脚本、又没装酒馆助手，换回原文时不会套用正则，调试视图会显示 `promptRegexApplied:false`。翻译 / 润色本身不受影响。
2. **禁用扩展后需要刷新页面**：入口是加载即执行的一次性初始化，没做 `disable` 钩子（和原来的脚本行为一致：原来也是停用后要刷新）。所以在这里禁用扩展后，面板会留在页面上直到刷新。
3. **配置存储**：配置写在酒馆的扩展设置里，属于明文、其他扩展可见。API 密钥没有写进去，仍然存在浏览器 `localStorage`。

## 下一步（可选）

- 要不要加扩展生命周期钩子：加 `disable` 钩子后可以在扩展管理器里直接停用并立刻移除面板，代价是要把内部的 `cleanup()` 暴露到对外句柄上，并且启用时可能仍需刷新页面才恢复。目前按「只拆不加」处理，未加。
- 要不要生成带 `css` 字段的版本：目前面板样式内联在 `index.js` 的模板字符串里，所以 `manifest.json` 没有 `css` 字段。
- 用不用把配置从 `extensionSettings` 换到别处：现在备份里会存最近两条消息的原文 / 译文，属于明文设置数据，量大时不利于设置文件体积。
